## 2. Decisions (pins)

**D1 (D-1 of the PREP) — Uniform panic.** Overflow of `+ - *` on non-literal Int produces a **UNIFORM PANIC** (exit 101, rustc message `attempt to add|subtract|multiply with overflow`) on **ALL** profiles (`arita build` debug, `--profile release`, `arita test`). Achieved per profile (PREP option O3b), **without changing the emitted Rust**. **Q1 RESOLVED (Engineer, 2026-10-03): YES O3b** (D1/D2 confirmed).

**D2 (D-2) — Per-profile mechanism.** The emitted Cargo.toml’s `[profile.release]` carries `overflow-checks = true` (alongside `opt-level = 3`; LTO off) and `arita test` invokes `rustc --test -O -C overflow-checks=on`. **Finding on workspaces (Q4, verified by reading `crates/arita-cli/src/package.rs`):** package workspaces do **not** use `emit_cargo_toml_with_hosts`: the root `Cargo.toml` comes from `emit_workspace_cargo_toml` (L186–L200, written at L300–L303) and only contains `[workspace]`, `resolver`, and `members`; each member’s `Cargo.toml` (L375 and L460) carries `[package]`, `edition = "2021"`, and dependencies; **no** own `[profile.*]`, nor `opt-level = 3`. Therefore the `emit_cargo_toml_with_hosts` change does **not** reach `arita build --profile release` on a package; to satisfy D1 there too, IMPL must add `[profile.release]` with `overflow-checks = true` to the workspace root `Cargo.toml` (change in `package.rs`: `emit_workspace_cargo_toml` today does not receive the profile). [H: that Cargo only applies `[profile.*]` from the workspace root is known Cargo behavior; not measured here.] The PREP (L123, L178) left this unchecked. **Q4 RESOLVED (Engineer, 2026-10-03): YES** — `[profile.release]` with `overflow-checks = true` in the workspace **ROOT** `Cargo.toml`; `emit_workspace_cargo_toml` must receive/emit the profile. It is **MEASURED in IMPL**; the Cargo claim stays [H] until measuring that Cargo applies `[profile.*]` only from the workspace root.

**D3 (D-3) — `/` and `%` do not change.** Rust’s panic (div0, `MIN ÷ −1`) is kept and documented; E0216/E0217 as today.

**D4 (D-4) — Literal-bound `MIN / -1`.** Today it surfaces as rustc E0100 (PREP L63), not E0217: ticket **B-292-1 (P3, HIR)**, outside this slice.

**D5 (D-5) — `known_int` is not flow-sensitive.** Const-fold is not flow-sensitive: an assignment inside an `if` overwrites `known_int` and that value survives outside the block; **measured false negative** (PREP L77 and L153). Ticket **B-292-2 (P2, HIR)**, outside this slice. **HYPOTHESIS (not measured):** the same defect could produce an E0217 **false positive** (e.g. `let a = 0; if c { a = MAX }; a + 1`); HIR must check it before deciding severity. **Q3 RESOLVED (Engineer, 2026-10-03):** B-292-2 stays P2, but HIR must check the E0217 false positive **BEFORE v1**; if confirmed, **it rises to P1** (still a hypothesis, not measured). **(→ ADR-294, P1; the “hypothesis” label is superseded: false positive MEASURED by PREP_B292_2_20261004)**

**D6 (D-6) — Declared asymmetry and reference addendum.** `v[i] op= x` (ADR-290 D5-ii) ⇒ `Err(0)` without panic; `a + b` ⇒ panic 101. ADR-290’s phrase “panic in debug, wrap in release” is **refined** via this path (the three routes of §1) **without rewriting ADR-290** (CLOSED): this ADR is the reference addendum. Also noted as an **amendment of ADR-045 §OUT**: “complex non-lit overflow” now has a runtime contract (D1).

**D7 (D-7) — Clippy lints.** `clippy::assign_op_pattern` (4 occurrences) and `identity_op` (1) in 4 of 63 positives emitted today (PREP L98): **OUTSIDE** this slice. **Q2 RESOLVED (Engineer, 2026-10-03):** redirected to **B-289-1 (P3)** (other rustc/clippy lints on positives); **B-292-3 → B-289-1 (P3)**, no own entry.

**D8 (D-8) — No amendment of ADR-289 or ADR-230.** Amending ADR-289 (PU2, 10 text tests) or ADR-230 does not apply because the emitted Rust **does not change** (O3b). Verify and declare at IMPL: 0 changes in emitted text (PREP L139 and L143–L147).

**D9 — Options not adopted.** **O1** (`checked` + `?` in fns `-> Result<_, Int>`; 62 of 63 positives would stop compiling without changing the `.arita`, PREP L103) remains as an opt-in language feature for v2: **B-292-4 (P3)**. **O2** (wrapping), **O3a** (textual panic: clashes with ADR-230 R0/R2, PREP L119), and **O4a** (saturating) are **NOT** adopted. **O4b** (only document the profile dependency) is the minimum if the Engineer rejects D1 (PREP L163).

**D10 — Path coverage.** **Every path that compiles emitted Rust must carry `overflow-checks`.** IMPL enumerates and covers, at minimum: R1–R5 of §1 (file and package `build`, debug and release; `arita test`) and `arita run` **if it existed** (it does not today, §1). Debug paths via `rustc` without `-O` (R1) and via Cargo `dev` (R2/R3 in debug) already panic today [V for R1, PREP L52; H for Cargo’s `dev` profile, not measured]. IMPL must also classify the `measure.rs` harnesses from the §1 finding (which ones build emitted Rust in release with their own `Cargo.toml`) and report any new path to the Engineer before touching it.
