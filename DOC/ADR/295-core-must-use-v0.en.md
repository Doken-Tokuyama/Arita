## 1. Decision and limits

**D1 — Contract = that of ADR-286, unchanged.** Only `Result<_, _>` surface values (Option and Unit stay out). **P2(a)** `let _: Result<T, E> = e` · **P2(b)** every unused `Result` binding (P4), with or without `_` prefix · **P2(c)** expression-statement of type `Result` that is neither a use nor a return tail. P4 (“use”) and S2-D2 (receiver, argument, and operand are uses; only the direct alias `let y: T = x` is transitive); A-1 (the tail of a fn → `Result` is a return, recursive through `if`/`else` and `match` at the tail; the tail of `main`/`Io<()>` is discard); A-2/A-3 (non-tail compound and bare `Ok(…)`/`Err(…)`); A-4 (named unused host-IO → E0272, explicit count in the re-scan); A-8/A-9. Bare `Err(_)`/`Err(_eN)` without `let` stays in v1 (P8).

**D2 — Single code: E0272, no new code.** Exact text `E0272: result error swallowed`, one diagnosis, no span, exit 1, empty stdout, no Rust emission. E0340 keeps its P1 host-IO forms. **E0348 is not approved**: B-286-9 is a separate slice (D6).

**D3 — Hooks in `arita-hir` (Engineer pin).** S2 hooks (i) in the `Let` arm **after** `bindings.insert` (P2(a)/(b)), (ii) in the `Expr` arm **after** the host-IO test (P2(c)), and (iii) in `check_body` (rest of the block and tail, A-1). The RHS is evaluated and typed **before** the hook (`eval_expr`, E0347, E0203, E0340): by S2-D1 the RHS error wins inside the same `let` and there is no E0272 cascade. “Unused” is computed **lexically over the rest of the block** (`expr_uses_ident` / `stmt_uses_ident` / `body_uses_ident`), **without** state in `BindingState` and without reading `known_int`. ADR-294 (CLOSED) did **not** touch `check_body` or `Let`/`Expr`: verified by reading (§2). The exact physical placement (inside `check_stmt_inner` or from `check_body` after `check_stmt`; PREP r4 R4.5.1 recommends the latter as order-equivalent and not editing what 294 rewrote) is fixed by IMPL, with two constraints: order identical to this pin and diff generated on the current tree.

**D4 — PREC-18 ACCEPTED, reusing E0343 (Engineer 2026-10-04).** It is the already-current order from ADR-286 §0 (“first offender in source order”) applied by `check()`; it is **not** new code and does not reopen E0340–E0343, and `index_assign_failed_span` is not touched. Pin wording: *E0343 (`?` outside a `Result` fn, ADR-278) beats every E0272 —from S1 or S2— whether earlier or later in source order; the only exception is ADR-283 §10, exclusive to E0344 (E0344 wins only if the body’s first error is exactly E0344 and its `IndexAssign` precedes the first `?`). An earlier E0272 that is the body’s first error yields to E0343 even against a later E0344.* Discriminating case `adr286_s2_prec_bare_e0344_qmark` (inline HIR test, no Measure id, no k): `v.push(0)` · `f(1)` · `v[0] = 2` · `let n: Int = f(2)?` · `print(n)` in `main` yields `E0344` today and **after S2 `E0343: question mark outside result fn`**; the control without `f(1)` keeps `E0344`. PREP r4 R4.4.2 adds PREC-18c (`v[0] = 2` · `f(1)` · `let n: Int = f(2)?` → `E0344`) and PREC-18b (`?` before the IA → `E0343`) as assertions of the same test. **D5 — Diagnosis order fixed (per fn, highest to lowest priority; PREP r4 R4.4.4).** E0346 (parse, ADR-291) › E0007 (prologue, builtin name) › E0343 (pre-pass, with the ADR-283 §10 exception) › inside the body, source order: the statement’s `eval_expr` errors (incl. **E0347**) → E0203 → E0340 → **S2 E0272** → next statement › S1 E0272 after `match` arm bodies › E0342 › deferred E0006. ## Reconciliation of ADR-286 L175 (A-10)

**Decision: ADR-286 is NOT edited.** Its current sha256 `b483188e38ba4ed27e6ade0c4d37a278cec8d71369af3c455dcc1f5837b6cd70` (294 lines) appears in sealed freezes: `DOC/reviews/MEASURE-ADR287-PKG-MEMBER-FREEZE-20261002.addendum.sha:8`, `…ADR288-EMIT-CLIPPY-FREEZE-20261003.sha:8`, `…ADR289-EMIT-UNUSED-PARENS-FREEZE-20261003.sha:7`, `…ADR290-INDEX-MUT-FREEZE-20261003.sha:8`, `…ADR292-INT-ARITH-RUNTIME-FREEZE-20261003.sha:8`, `…ADR293-UNDECLARED-CALL-FREEZE-20261004.sha:6`, `…ADR294-KNOWN-INT-SCOPE-FREEZE-20261004.sha:6`, and `…ADR291-MUTEX-REJECT-FREEZE-20261004.sha:6`; editing it would break `shasum -a 256 -c` for all of them. The GATEs do not cite that sha.

**What they say today.** L175 (row `core10-must-use-emit-ban`, §2): “over all Rust emitted from core10 sources: zero `let _ =` applied to a `Result` surface value, with the P6 exclusions (`{ let _ = m.insert(k, v); }` from `put`; `{ let _ = {t}.await; }`, the latter to be verified by Codegen; type-safe after S1b(a), A-10 re-verification after CLOSED S1b and before S2 GO IMPL); plus zero `.unwrap()`/`.expect(`/`panic!(` (241)”.
